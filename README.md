# 기존 로또 사이트 업데이트 — v2

이 ZIP은 기존 GitHub Pages 사이트의 업데이트용입니다. `data` 폴더를 포함하지 않습니다. 이미 수집한 `data/lotto.json` 및 기존 `data/weekly.json`을 그대로 유지하세요. 처음 설치하는 빈 저장소용 묶음은 아닙니다.

## 업데이트 순서

1. ZIP의 내용물을 기존 저장소 `main` 브랜치 최상위에 업로드하여 같은 이름의 파일을 교체합니다. 바깥 폴더나 ZIP 자체만 올리지 마세요.
2. `.github/workflows/lotto-pages.yml`도 교체합니다. 숨김 폴더가 보이지 않으면 GitHub 파일 편집 화면에서 제공된 내용을 붙여 넣습니다.
3. 기존 `data` 폴더는 삭제·교체하지 않습니다. 새 `data/study.json`은 최초 자동 실행에서 생성됩니다.
4. Settings → Pages → Source는 GitHub Actions를 유지합니다.
5. Actions → Lotto Pages → Run workflow를 실행합니다. 수집 후 v2 구매용 기록과 연구용 기록을 저장·커밋·배포합니다.
6. 페이지를 새로고침하여 `weekly-five-v2-disjoint`와 ‘1241회 이후 저빈도 연구 추적’ 영역을 확인합니다.

기존에 cron-job.org를 연결했다면, 워크플로 교체 후 `schedule` 블록을 다시 삭제하여 이중 예약을 방지하세요. `workflow_dispatch`와 파일 이름은 유지하여 기존 호출 주소를 사용할 수 있습니다. 실제 수집·배포는 계속 Actions에서 수행하므로 실행 대기는 남습니다.

## 구매용 5게임

새 버전은 45개 번호 중 30개를 회차·버전에 따라 재현 가능하게 선택한 뒤 6개씩 나눕니다. 5게임 전체에서 번호가 겹치지 않습니다. 같은 회차·버전에서는 기기와 실행 횟수에 무관하게 동일한 번호입니다. 매주 다음 회차에서는 번호가 바뀝니다.

v1과 v2는 번호가 다릅니다. 이미 v1 번호를 구매했다면 그대로 해당 회차의 구매 번호로 관리하세요. 업데이트가 기존 복권 번호를 바꾸지는 않습니다. 기록 표에 버전과 당시 번호를 함께 표시합니다.

기존 `weekly-five-v1` 알고리즘은 과거 기록 검증용으로 보존했습니다. 같은 회차에 v1·v2 기록이 각각 존재할 수 있고, 번호와 최초 시각을 덮어쓰지 않습니다. 이 기기 기록 가져오기도 회차+버전 기준으로 병합합니다.

이 구성의 목적은 적어도 한 게임이 당첨될 확률을 개선하는 것입니다. 공정하고 독립적인 6/45 추첨에서 무작위의 서로 다른 5게임 평균 대비, 5등 이상 확률은 약 11.3624%에서 11.8679%로 바뀝니다. 4등 이상 확률은 약 0.696741%로 해당 목표의 이론적 상한을 달성합니다. 1등 확률은 5/8,145,060으로 동일합니다. 5등 이상 목표의 전역 최적성을 증명한 것은 아니며 기대 수익 증가·특정 번호 예측 우위가 입증된 것도 아닙니다. 수치는 조합론 계산입니다.

## 연구용 사전 기록

- 시작 기준: 1241회 이후.
- 모델: `cold100-prospective-v1`, 직전 100회 저빈도 가설.
- 출력: 연구용 번호 6개인 **1게임**과 45개 번호의 주변 출현 확률. 구매용 5게임에 추가되는 구매 지시가 아닙니다.
- 기존 검증 함수의 균등 확률 보정(100회 분량 사전값)과 저빈도 반사를 사용합니다. 합계 확률은 6, 각 값은 0~1입니다.
- 동점은 회차·모델 버전·번호의 SHA-256 값으로 순서를 정합니다. 기존 과거 검증의 동점 기대 일치 수와 달리, 실제 추적에서는 한 개의 고정된 조합을 평가합니다.
- 직전 100회에 누락이 있으면 연구 기록을 보류합니다. 이미 결과가 있는 회차 또는 예정 마감 이후 회차는 새로 기록하지 않습니다.
- 학습 시작/종료 회차, 학습 번호 자료의 SHA-256 해시, 예측 번호·확률, 최초 저장 시각, 예정 마감 시각을 저장합니다.
- 매주 수집·기록 작업에서 `data/study.json`에 추가합니다. 이전 기록은 재계산·덮어쓰기하지 않습니다.
- 대상 회차의 예상 마감은 직전 공식 추첨일에서 7일 뒤 한국 시간 20:00입니다. 실제 일정이 변경되면 설정을 수정해야 합니다. 날짜가 불명확하거나 이미 지났으면 기록하지 않습니다.

1241회가 발표된 뒤 업데이트하더라도 1241회 기록을 소급 생성하지 않습니다. 추적 시작 기준은 1241회지만 실제 평가는 업데이트 이후 마감 전에 저장된 회차부터입니다.

## 1241회 이후 평가

사전 기록과 공식 당첨 결과가 모두 있을 때만 집계합니다. 실제 추첨일의 한국 시간 20:00 이후 저장된 기록이나 날짜 확인 불가 기록은 제외합니다. 미기록·제외 회차는 별도로 표시하며, 무당첨으로 가정하거나 표본 수에 포함하지 않습니다.

주 지표는 번호별 Brier 오차(낮을수록 좋음)이고 균등 기준은 0.11555556입니다. 보조 지표는 연구용 1게임의 평균 번호 일치 수(균등 기준 0.8)입니다. 100개 평가 기록 단위로 검토하며 유리한 시점만 골라 결론을 내리지 않습니다. 자동 유의성 판정이나 모델 교체 기능은 없습니다. 코드와 모델 설정을 바꾸면 새 버전으로 별도 평가해야 합니다.

저장 시각·JSON은 독립 인증이 아니며 구매 증명도 아닙니다. 공개 커밋 시각과 작업 로그를 별도 확인하세요. 학습 해시는 자료 변경 여부 대조용이지 시각 인증이나 예측력 증거가 아닙니다. 번호·확률의 형식 검증이 원본 자료의 진실성을 보증하는 것도 아닙니다.

## 유지되는 기능

전체 이력 수집·누락 보충·중간 저장 재개, 공식 결과 조회, 수동 당첨 자료 입력·가져오기, 출현 통계, 기존 과거 가설 검증, 구매용 기록 내보내기·가져오기와 등수 대조는 유지됩니다. 공식 결과 대조는 브라우저의 수동 수정 자료가 아닌 배포된 공식 자료를 사용합니다.

수집 또는 기록 작업이 실패해도 가능한 기존 자료를 보존·배포한 뒤 워크플로에 실패를 표시합니다. 연구 기록에 오류가 있으면 페이지 상태와 Actions 로그를 확인하세요. 예약은 기본 일요일·월요일 한국 시간 오전 9:17입니다.

## 검증 범위

26개 자동 테스트에서 30개 번호 비중복, 회차·기기 간 고정 출력, v1 과거 번호의 완전 일치, 두 버전 기록 공존, 마감 경계, 미래 결과가 포함된 연구 기록 거부, 누락 자료 거부, 미기록·늦은 기록의 평가 제외, 기존 수집·등수 판정 기능을 확인했습니다. 모의 DOM에서 페이지 초기화·번호 생성도 확인했습니다. 실제 GitHub 저장소에 이번 수정본을 업로드·배포한 상태는 아닙니다.

이전 분석에서 사용자 사이트의 1~1240회 JSON을 내려받아 누락·중복 없는 1240개 자료를 확인했습니다. 연구에서 확인한 저빈도 방식의 일부 좋은 결과는 예측 우위 입증이 아니므로 구매용 가중치에 반영하지 않았습니다.
