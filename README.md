# 로또 분석 · 번호 선택 — GitHub Pages용

로또 6/45 전용 정적 웹페이지입니다. 번호 생성, 출현 빈도 분석, 회차 입력, JSON/CSV/Excel 가져오기, JSON 내보내기를 제공합니다. 페이지의 토큰 입력이나 GitHub Issues 동기화 기능은 없습니다. 서버·데이터베이스 없이 GitHub Pages에서 실행됩니다.

## 처음 배포하기

1. ZIP을 압축 해제합니다. GitHub에서 기본 브랜치가 `main`인 저장소를 준비합니다. GitHub Free 사용 시 공개 저장소에서 Pages를 사용할 수 있습니다.
2. **압축 해제한 폴더 안의 내용물**을 저장소 최상위에 업로드합니다. `index.html`, `data`, `scripts`, `tests`, `.github/workflows/lotto-pages.yml`, `.nojekyll`이 모두 포함되어야 합니다. ZIP 자체나 바깥 폴더 하나만 올리면 실행되지 않습니다.
3. 점으로 시작하는 `.github` 폴더가 파일 선택창에서 보이지 않으면 GitHub의 **Add file → Create new file**에서 파일명을 `.github/workflows/lotto-pages.yml`로 입력한 뒤 제공된 파일 내용을 붙여 넣습니다. `.nojekyll`도 같은 방법으로 빈 파일을 만듭니다.
4. 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다. 별도 추천 워크플로 템플릿은 추가하지 않습니다.
5. **Actions → Lotto Pages → Run workflow → main → Run workflow**를 실행합니다. 업로드 직후 Pages 설정 전 실행이 실패했어도 이 단계에서 다시 실행할 수 있습니다.
6. 실행의 `Deploy` 단계에 나온 주소 또는 Settings → Pages의 사이트 주소를 엽니다. 휴대폰·태블릿·PC에서 같은 주소를 사용하세요. 최신 Chrome, Edge, Safari, Firefox를 대상으로 합니다.

GitHub 설정 기준: [공식 Pages 배포 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## 자동 수집과 저장

- 일요일·월요일 한국 시간 오전 9:17에 공식 결과 수집을 시도합니다. 월요일은 재시도 용도입니다. `main`에 파일을 올리거나 수동 실행할 때도 수집합니다.
- GitHub Actions가 공식 페이지의 최신 회차를 읽고 공식 JSON 응답을 검증합니다. 결과는 `data/lotto.json`에 저장하고 저장소에 커밋한 뒤 같은 작업에서 페이지를 배포합니다. 개인 액세스 토큰은 필요하지 않습니다.
- 수집에 실패하면 기존 회차를 유지하고 실패 상태를 사이트에 배포한 뒤 작업을 실패로 표시합니다. Actions의 빨간 표시만으로 사이트 배포까지 실패했다고 판단하지 말고 `Deploy` 단계와 사이트 상태를 함께 확인하세요.
- 현재 묶음에는 당첨 결과를 임의로 채워 넣지 않았습니다. 최초 수집은 공식 응답에 포함된 최근 회차만 가져옵니다. 전체 역대 회차 일괄 수집 기능은 없습니다. 초기 과거 자료는 가져오기를 이용하세요.
- 페이지의 **최신 파일 확인**은 이미 배포된 JSON을 다시 읽습니다. 공식 사이트를 직접 크롤링하거나 Actions를 즉시 실행하는 버튼이 아닙니다.
- GitHub 일정 실행은 지연·누락될 수 있고, 공개 저장소는 활동이 60일 없으면 일정 실행이 비활성화될 수 있습니다. Actions 탭에서 확인하고 다시 활성화하세요. [일정 실행 공식 안내](https://docs.github.com/actions/using-workflows/events-that-trigger-workflows#schedule)
- 브랜치 보호나 조직 정책으로 봇의 커밋이 차단되면 `Save collection state`가 실패할 수 있습니다. 해당 저장소 정책에 맞게 봇의 쓰기 또는 별도 배포 구조를 설정해야 합니다.

## 기기별 자료

`data/lotto.json`의 공식 결과는 모든 기기에 공통으로 배포됩니다. 직접 입력·수정·삭제한 회차는 해당 브라우저의 localStorage에만 저장됩니다. 수정한 회차는 공식 자료를 새로 읽어도 유지되고, 삭제한 회차는 해당 기기에서 숨깁니다. **이 기기 수정 초기화**로 공식 결과만 다시 표시할 수 있습니다.

직접 입력한 자료를 다른 기기로 옮기려면 **자료 내보내기 → 다른 기기에서 자료 가져오기**를 사용하세요. 모든 기기에서 개인 자료까지 실시간 공동 편집하려면 별도 인증 서버·데이터베이스가 필요합니다. 이 정적 버전에는 포함되지 않습니다. 이전 사이트의 브라우저 저장 자료는 주소가 달라 자동 이전되지 않으므로 먼저 내보내세요.

## 자료 형식

JSON은 이 페이지의 내보내기 파일 또는 아래 구조를 지원합니다. 숫자는 문자열이 아닌 JSON 숫자여야 합니다. 같은 파일 안의 중복 회차, 중복 번호, 범위 오류, 보너스 중복은 파일 전체를 거부합니다.

```json
{"draws":[{"round":1,"nums":[10,23,29,33,37,40],"bonus":16}]}
```

CSV/Excel은 첫 시트의 8열 `회차,번호1,번호2,번호3,번호4,번호5,번호6,보너스` 또는 맨 앞에 No 열을 추가한 9열을 지원합니다. 첫 행의 제목은 선택 사항입니다. CSV는 UTF-8의 단순 숫자 표를 사용하세요. 파일 크기는 최대 10 MB입니다. Excel 읽기는 [SheetJS 0.20.3 공식 배포본](https://docs.sheetjs.com/docs/getting-started/installation/standalone/)을 필요할 때 로드하므로 온라인 연결이 필요합니다. 번호 생성·JSON·CSV 기능은 이 라이브러리 없이 동작합니다.

## 알고리즘과 해석

- 기본값은 암호학적 난수와 편향 없는 정수 추출을 사용하는 무작위 선택입니다. 각 조합에서 중복 번호를 금지하고 한 번에 출력하는 동일 조합도 제거합니다.
- 포함·제외·합계 범위·조합 사이 공통 번호 수를 검증합니다. 제한 내에서 요청 개수를 확보하지 못하면 오류를 알리고 조건을 임의로 풀지 않습니다. 후보 검색 실패가 수학적 불가능을 뜻하지는 않습니다.
- 생일 번호 집중 회피는 1~31 번호가 5개 이상인 조합을 후순위로 배치하는 실험 옵션입니다. 실제 구매 분포를 알지 못하므로 공동 당첨 감소·기대 수익 개선은 검증되지 않았습니다. 기본값이 아닙니다.
- 과거 당첨 조합 제외와 번호 공통 수 제한은 취향 옵션입니다. 어떤 특정 조합도 과거 출현 때문에 다음 회차 확률이 변하지 않습니다.
- 6/45 조합은 8,145,060개입니다. 서로 다른 N게임을 같은 회차에 구매하면 1등 당첨 확률은 N / 8,145,060입니다. 번호 선택 규칙은 개별 조합의 당첨 확률을 높이지 않습니다.
- 출현 빈도 검정은 회차 내 비복원 추출을 반영해 Pearson 통계량에 44/39를 곱하고 자유도 44의 근사 분포를 사용합니다. 38회 미만은 p값 해석을 보류합니다. 이 검정은 번호별 주변 빈도만 보며 독립성이나 예측 가능성을 검증하지 않습니다.
- 월 예산은 1게임 1,000원, 52주/12개월로 환산해 초과 여부를 표시하는 계산 기능입니다. 결제·구매를 실행하거나 금액을 강제 제한하지 않습니다.

## 검증과 한계

Node.js 22에서 `node --test tests/*.test.mjs`로 9개 테스트를 통과했습니다. 조건부 번호 생성, 조합 중복, 통계 계산, 자료 검증, 기기 내 수정 병합, 공식 응답 파싱, 수집 실패 시 원본 보존, HTML 스크립트 문법을 확인했습니다.

제작 환경의 공식 사이트 실접속은 시간 초과로 실패했습니다. GitHub 실행 환경에서의 실제 수집 성공과 최초 배포는 아직 확인하지 않았습니다. 공식 사이트의 응답 형식·접근 정책이 바뀌면 `scripts/collector.mjs`를 수정해야 합니다. UI에는 최근 수집 시도·성공 시각과 실패 사유를 표시합니다.

`index.html`은 단독으로도 번호 생성과 수동 자료 관리에 사용할 수 있지만, 자동 갱신을 사용하려면 이 묶음 전체를 배포해야 합니다. 개발 시 알고리즘은 HTML 안과 `scripts/algorithm.mjs` 양쪽에 동일하게 반영하세요. 테스트가 두 사본의 일치 여부를 확인합니다.
